Security & Cryptography

CipherVault

A tokenization engine replacing sensitive PII fields with secure tokens before data enters downstream systems and reporting pipelines, with tenant-aware access isolation.

PROBLEM STATEMENT

Storing raw PII (account numbers, customer identity) in application and reporting pipelines risks exposure across institutional clients sharing the same multi-tenant system.

ARCHITECTURE OVERVIEW

Spring Boot service backed by PostgreSQL and JPA, using Spring Security to enforce tenant-aware data access and a role-based detokenization workflow for accessing sensitive fields.

KEY FEATURES
  • Tokenization engine replacing sensitive PII fields with secure tokens so downstream services operate only on tokenized data
  • Tenant-aware data access enforcing logical isolation between institutional clients in a shared multi-tenant architecture
  • Role-based detokenization workflow requiring reason codes and audit logging for every sensitive data access
Java Spring Boot Spring Security PostgreSQL JPA

Privacy & Peer Support

HeartBench

Privacy-first peer support and study-matching platform connecting students in real time by need category and location, without exposing their identity.

PROBLEM STATEMENT

Public broadcast-style matching exposes who's asking for support and where — students need a way to find peer or study matches nearby without giving up their privacy.

ARCHITECTURE OVERVIEW

Mobile-first React PWA backed by a Node.js/Express service using Socket.io for real-time matching and MongoDB's 2dsphere geospatial indexing for location-zone proximity matching.

KEY FEATURES
  • Privacy-first matching engine using pseudonymized identities and location fuzzing, with secure server-side pairing instead of public broadcast matching
  • Real-time request-response matching via Socket.io, targeting sub-3-second match notification delivery
  • Category-based escalation logic routing high-sensitivity requests toward campus counseling resources rather than peer-only matching
React (PWA) Node.js Express.js Socket.io MongoDB (Geospatial)

FinTech & System Resilience

RelayPay

A payment failover platform that reactively relays a failed transaction to a trusted family/circle member's linked bank account, verified after the failure occurs.

PROBLEM STATEMENT

Payment failures leave the payer stuck with no fallback. Existing approaches like NPCI UPI Circle rely on proactive delegation set up in advance — RelayPay instead triggers failover reactively, only once a payment failure is verified.

ARCHITECTURE OVERVIEW

Native Android client (Java, MVVM + Clean Architecture) backed by a Node.js/Express/MongoDB service layer. The backend runs a failover state machine with enforced transitions, a double-entry ledger using MongoDB sessions and optimistic locking, and a swappable bank-adapter interface currently backed by a mock provider.

KEY FEATURES
  • Reactive failover engine relaying a failed payment to a linked bank account within the user's family circle after verified failure
  • Double-entry ledger service with MongoDB session-based transactions and optimistic locking for consistency
  • JWT auth with refresh token rotation, OTP gating, and brute-force lockout protection
Java (Android) Node.js Express MongoDB JWT
